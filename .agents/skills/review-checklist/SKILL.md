# Review checklist

Read the entire brief the user identifies, including any appendices that form part of it. If no brief is identified or it cannot be read, ask for its location or text.

Check these four things using evidence from the brief:

1. **Ownership.** Does it name the person or role accountable for the brief and its outcome? An audience or a list of contributors alone does not establish ownership. Note conflicting assignments.
2. **How we know it worked.** Does it describe an observable outcome and how success will be judged? Look for a measure or verifiable criterion, the evaluation period where relevant, and a source or method of checking. Judge these in proportion to the brief; do not require numeric targets for every outcome. Distinguish proposed thresholds from approved decisions.
3. **Consistent scope.** Compare the opening problem, intended users, proposed change, exclusions, success measures, and acceptance criteria. Flag contradictions, unexplained additions, or promises that the proposed work cannot deliver. Explicitly explained scope changes are acceptable.
4. **Problem before fix.** Does the reader learn who is affected, what is happening, and why it matters before the solution is introduced? A title or short summary may name the solution first; assess the explanatory body rather than heading order alone. Keep observations separate from hypotheses about their cause.

Return a concise table with one row per check: **Pass**, **Needs work**, or **Cannot assess**, the supporting quotation or section reference, and the smallest useful improvement for any gap. Link local evidence to the file and line when available. Never invent missing owners, measurements, approvals, or evidence.

End with the highest-priority gaps, if any. If all four checks pass, say so without adding unrelated review requirements. Review the supplied brief as it stands; edit it only when the user requests changes. Preserve the author's wording and scope in any suggested edits.
